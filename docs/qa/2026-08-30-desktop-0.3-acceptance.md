# Desktop BehaviorLog 0.3 acceptance

This follow-up verifies Tickets 109–114 against the stable BehaviorLog 0.3
implementation. It supplements the earlier
[native boundary evidence](2026-08-30-desktop-native-boundary.md).
Only synthetic local data is used. No hosted rollout or publication is included.

## Defects found by integrated acceptance

- The real Supabase contract reproduced invented local configuration lineage
  for an imported Occurrence. Migration
  `20260831001533_preserve_unknown_imported_configuration_lineage.sql` was
  applied locally after the failing assertion established the defect.
- Native exports emitted standard `other` / `delivered` Interventions that
  import validation and passive-history storage rejected. The shared importer
  and both database adapters require matching passive-history support.
  Imported history must never create operational reminder deliveries.
- Re-export after self-restore duplicated preserved configuration history from
  successive import ledgers. Canonical deduplication must preserve distinct
  provenance and keep Occurrence lineage references attached to retained events.
- Actual WKWebView self-import preview proposed creating an existing passive
  Note again. The export uses its local record ID, while merge matching only
  recognized original external IDs and earlier mappings. Apply was not run.
  Passive Note/Intervention matching must recognize exact re-exported records
  without merging distinct records or ignoring changed content/provenance.
- Existing-record assembly used the Behavior creation date for current schedule
  periods. Exports use captured configuration boundaries. Self-import must
  compare the same period while retaining safe replay of accepted older bundles.
